# 2026-05-17 작업 로그

## 작업 원칙

- 중간 질문은 작업 방향 변경으로 간주하지 않고, 기존 예정 작업은 사용자 확인 없이 바꾸지 않는다.
- Flutter 명령은 병렬 실행하지 않고 순차 실행한다.
- 서브 에이전트는 독립 작업이 명확할 때만 사용자에게 먼저 권장한다.
- 실제 Android 기기 검증은 기기가 준비될 때까지 보류한다.

## 완료한 작업

### 판별 근거 저장 보강

- `TransactionCandidate`, `ClassificationResult`를 SQLite에 별도 저장하도록 파이프라인을 보강했다.
- raw notification 중복 여부를 `sourceHash`로 먼저 확인해 같은 원천 이벤트의 재처리를 막았다.
- 파싱 후보와 분류 결과를 최종 지출과 분리해 추적 가능한 구조로 정리했다.

### 상세 화면 판별 근거 표시

- 상세 화면에 `판별 근거` 카드를 추가했다.
- 연결된 후보 ID별로 파싱 후보 정보를 표시한다.
- 표시 항목:
  - 가맹점
  - 금액
  - 결제 수단 힌트
  - 파싱 상태와 파싱 신뢰도
  - 실제 지출 여부
  - 중복 의심 여부
  - 이체/충전성 여부
  - 검토 필요 여부
  - 분류 신뢰도
  - reason code
- 후보 ID 기반 단건 조회를 위해 repository 계약과 메모리/SQLite 구현을 확장했다.
- Riverpod provider를 추가해 상세 화면에서 후보와 분류 결과를 비동기로 조회한다.

## 현재 평가

- 자동 수집 원천 데이터, 파싱 후보, 판별 결과, 최종 지출이 분리되어 이후 디버깅과 사용자 설명 가능성이 좋아졌다.
- 사용자가 상세 화면에서 “왜 지출로 들어왔는지”를 확인할 수 있게 되어 MVP 신뢰도를 올리는 기반이 생겼다.
- 아직 실제 Android 기기 검증이 없으므로 권한, 백그라운드 수신, 제조사별 제한은 미검증 상태다.
- UI는 여전히 기능 확인용이며 전달받은 시안 수준의 polish는 후속 작업이다.
