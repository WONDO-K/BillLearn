# 2026-05-17 작업 로그

## 작업 원칙

- 중간 질문은 작업 방향 변경으로 간주하지 않고, 기존 예정 작업은 사용자 확인 없이 바꾸지 않는다.
- Flutter 명령은 병렬 실행하지 않고 순차 실행한다.
- 서브 에이전트는 독립 작업이 명확할 때만 사용자에게 먼저 권장한다.
- 실제 Android 기기 검증은 기기가 준비될 때까지 보류한다.

## 완료한 작업

### 판별 근거 저장 보강

- `TransactionCandidate`, `ClassificationResult`를 SQLite에 별도 저장하도록 파이프라인을 보강했다.
- raw notification 중복 여부를 `sourceHash`로 먼저 확인해 같은 원천 이벤트의 재처리를 막았다.
- 파싱 후보와 분류 결과를 최종 지출과 분리해 추적 가능한 구조로 정리했다.

### 상세 화면 판별 근거 표시

- 상세 화면에 `판별 근거` 카드를 추가했다.
- 연결된 후보 ID별로 파싱 후보 정보를 표시한다.
- 표시 항목:
  - 가맹점
  - 금액
  - 결제 수단 힌트
  - 파싱 상태와 파싱 신뢰도
  - 실제 지출 여부
  - 중복 의심 여부
  - 이체/충전성 여부
  - 검토 필요 여부
  - 분류 신뢰도
  - reason code
- 후보 ID 기반 단건 조회를 위해 repository 계약과 메모리/SQLite 구현을 확장했다.
- Riverpod provider를 추가해 상세 화면에서 후보와 분류 결과를 비동기로 조회한다.

### 확인 필요 거래 검토 흐름

- 홈 `확인 필요` 섹션의 거래에 `검토하러 가기` CTA를 추가했다.
- 홈의 확인 필요 거래를 누르면 해당 거래 상세 화면으로 이동한다.
- 홈/내역에서 확인 필요 거래에 `실제 지출인지 확인해주세요` 안내 문구를 표시한다.
- 상세 화면의 `맞아요`/`아니요` 피드백으로 검토를 마무리할 수 있는 흐름을 연결했다.

### 파서 샘플 확장

- 카드사 문자에서 `금액 + 일시불 + 가맹점` 형태를 처리하도록 보강했다.
- 카카오뱅크 체크카드처럼 `가맹점 + 금액` 순서로 오는 알림을 처리하도록 보강했다.
- 카카오페이처럼 줄바꿈으로 `결제완료 / 가맹점 / 금액`이 분리된 포맷을 처리하도록 보강했다.
- payment method 추출에서 title과 body를 함께 활용하도록 개선했다.

### 은행 이체성 알림 분류 보강

- `보냈어요`, `받았어요`, `받는분`, `보낸분`, `님에게` 같은 은행/간편송금 자연어 문구를 이체성 알림으로 분류하도록 보강했다.
- 사람 간 송금과 입금 알림이 실제 지출로 저장되지 않도록 파이프라인 테스트를 추가했다.
- 분류 키워드 그룹에 짧은 주석을 추가해 어떤 목적의 필터인지 바로 파악할 수 있게 했다.

### 파서/분류 fixture 분리

- 파서 샘플을 `test/fixtures/payment_parser_cases.json`으로 분리했다.
- 분류 정책 샘플을 `test/fixtures/expense_classifier_cases.json`으로 분리했다.
- 파서/분류 테스트는 fixture 파일을 읽어 검증하도록 정리했다.
- 샘플 추가 위치를 바로 찾을 수 있도록 테스트 파일에 짧은 안내 주석을 추가했다.

### 취소/환불 알림 분류 보강

- `승인취소`, `결제취소`, `환불`, `매출취소` 같은 취소/환불성 알림을 실제 지출로 저장하지 않도록 보강했다.
- 카드 승인취소와 네이버페이 환불완료 fixture를 추가했다.
- 승인취소 알림이 파이프라인에서 지출로 저장되지 않는 테스트를 추가했다.
- 취소/환불 키워드 그룹에 짧은 주석을 추가해 별도 회계 처리 전까지 제외하는 의도를 명시했다.

## 현재 평가

- 자동 수집 원천 데이터, 파싱 후보, 판별 결과, 최종 지출이 분리되어 이후 디버깅과 사용자 설명 가능성이 좋아졌다.
- 사용자가 상세 화면에서 “왜 지출로 들어왔는지”를 확인할 수 있게 되어 MVP 신뢰도를 올리는 기반이 생겼다.
- 확인 필요 거래가 홈에서 상세 검토까지 이어지므로 MVP의 수동 보정 루프가 더 명확해졌다.
- 파서가 단일 고정 포맷에서 조금 벗어난 실제 알림 형태를 일부 처리할 수 있게 됐다.
- 은행/간편송금 자연어 문구가 지출로 저장되는 오탐 위험이 줄었다.
- 샘플이 fixture 파일로 분리되어 실제 알림 포맷을 계속 추가하기 쉬워졌다.
- 취소/환불 알림이 지출 총액을 부풀리는 위험을 1차로 막았다.
- 아직 실제 Android 기기 검증이 없으므로 권한, 백그라운드 수신, 제조사별 제한은 미검증 상태다.
- UI는 여전히 기능 확인용이며 전달받은 시안 수준의 polish는 후속 작업이다.
