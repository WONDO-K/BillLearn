## 완료한 작업

### Android raw event pending queue 추가

- Android native에서 알림/SMS raw event를 `SharedPreferences` pending queue에 먼저 저장하도록 추가했다.
- Flutter가 시작될 때 `drainPendingRawEvents` method channel로 pending event를 회수해 기존 raw notification pipeline에 넣도록 연결했다.
- live EventChannel 이벤트와 pending drain 이벤트가 중복될 수 있으므로 기존 `sourceHash` 중복 방어를 유지했다.
- `NotificationListenerService`, `SmsReceiver` 모두 새 queue 저장 경로를 사용하도록 변경했다.

### Pending queue debug 진단 표시

- Android bridge에 `getPendingRawEventCount` method channel 계약을 추가했다.
- native pending queue의 현재 잔여 건수를 설정 화면 개발자 도구 카드에 표시하도록 했다.
- 실제 기기 검증 시 `대기 중 원천 이벤트 N건`과 `수집 진단` 저장 건수를 분리해서 볼 수 있게 했다.

### 가맹점 로고 asset 적용 구조 정리

- `MerchantVisual`에 `assetPath`를 추가해 정식 로고 파일이 생기면 fallback 라벨 대신 `Image.asset`을 사용할 수 있게 했다.
- 가맹점 alias와 시각 정보를 catalog entry로 분리해 홈/내역/상세가 같은 매핑을 쓰도록 정리했다.
- 정식 로고 파일이 없거나 로딩에 실패하면 기존 fallback 라벨이 계속 보이도록 했다.
- `docs/merchant-logo-assets.md`에 로고 파일 위치, 파일명, pubspec 등록, catalog 수정 절차를 정리했다.

## 현재 평가

- 앱이 늦게 켜져도 native receiver/service가 실행됐다면 raw event를 다음 시작 시 회수할 수 있는 최소 안전장치가 생겼다.
- 설정 화면에서 pending queue 잔여 건수를 볼 수 있어 실제 기기 검증 때 누락 지점을 더 빨리 분리할 수 있다.
- 실제 Android 기기에서 강제 종료 후 receiver/service가 실행되는지는 제조사/OS 정책 영향을 받으므로 아직 미검증이다.
- 정식 가맹점 로고 asset은 아직 없지만, asset이 준비되면 catalog 한 곳만 수정해 주요 거래 화면에 반영할 수 있다.
