# 2026-05-18 작업 로그

## 작업 원칙

- 사용자의 중간 질문은 기존 예정 작업 변경으로 간주하지 않는다.
- 커밋 메시지는 `[Feat]`, `[Fix]`, `[Docs]` 같은 머릿말과 한국어 설명을 사용한다.
- UI 작업은 에뮬레이터 검증을 우선하되, 실제 데이터 주입 경로가 없는 화면은 테스트 검증을 먼저 완료한다.

## 완료한 작업

### 상세 화면 1차 UI polish

- 상세 화면 상단을 가맹점, 상태, 금액이 먼저 보이는 요약 카드로 재구성했다.
- `거래 정보` 카드를 추가해 결제 시간, 상태, 확인 방식, 동기화, 카테고리를 정리했다.
- 피드백 영역을 `이 거래가 실제 지출인가요?` 카드로 분리해 사용자가 해야 할 일을 명확히 했다.
- `판별 근거` 카드를 홈/내역과 같은 rounded white card 스타일로 정리했다.
- 파싱 후보, 분류 chip, 신뢰도, reason code 표시를 더 읽기 쉬운 간격과 색상으로 조정했다.
- 제외된 거래는 상단 금액에 취소선을 적용해 총액에서 제외된 거래임을 시각적으로 드러내도록 했다.

## 현재 평가

- 홈/내역/상세의 주요 조회 흐름이 같은 브랜드 톤으로 맞춰졌다.
- 상세 화면은 이제 단순 데이터 나열보다 “이 거래가 무엇이고, 왜 이렇게 판별됐고, 사용자가 어떻게 수정할 수 있는지”가 더 분명하다.
- 상세 화면 실제 에뮬레이터 스크린샷은 아직 보류 상태다. 현재 앱에 샘플 거래를 쉽게 주입하는 개발자용 루트가 없어 상세 화면으로 들어갈 데이터가 필요하다.
- 다음 UI 검증 품질을 높이려면 개발자용 seed/debug action 또는 테스트 데이터 주입 도구를 추가하는 것이 좋다.
