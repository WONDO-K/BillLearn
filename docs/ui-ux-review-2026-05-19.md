# BillLearn UI/UX 1차 회고

작성일: 2026-05-19

이 문서는 에뮬레이터 기준으로 확인한 BillLearn의 1차 UI/UX 상태를 정리한다. 목적은 시안 대비 현재 구현 수준을 고정하고, 다음 polish 작업의 우선순위를 명확히 하는 것이다.

## 기준 자료

- 디자인 기준: `docs/assets/brand/core-ui-screens.png`
- 현재 UI 스크린샷: `docs/ui-screenshots.md`
- 주요 검증 기기: Android emulator `emulator-5554`
- 현재 구현 범위: Android-first Flutter MVP

## 현재까지 맞춰진 부분

### 홈

- 상단 구조를 `홈` 타이틀과 알림 아이콘으로 재정렬했다.
- 히어로 카드를 `이번 달 총 지출`, 월 지출 한도, 진행률, 전월 대비 상태, 검토 알림 수 중심으로 재구성했다.
- 브랜드 마스코트를 히어로 카드와 빈 상태 카드에 적용했다.
- `AI가 헷갈린 거래` 표현을 `빌런의 인사이트`로 바꿔 브랜드 톤에 맞췄다.
- 최근 거래를 흰 rounded card 안의 compact list로 바꿨다.
- 정식 로고 asset 없이도 `merchantName` 기반 fallback 아이콘으로 시각 밀도를 높였다.

### 내역

- 확정/검토/제외 상태를 함께 보여주는 거래 리스트 기본 구조가 있다.
- 확인 필요 거래가 일반 지출과 구분된다.
- 상세 화면으로 진입할 수 있는 거래 중심 흐름은 동작한다.

### 상세

- 거래 금액, 거래 정보, 사용자 피드백, 판별 근거를 한 화면 흐름 안에 배치했다.
- `맞아요` / `아니요` 피드백 동선을 제공한다.
- 파싱 후보, 판별 chip, 신뢰도, reason code가 하단에서 확인된다.

### 설정

- 알림 접근 권한, SMS 권한, 개발자용 샘플 데이터 생성, 수집 진단이 한 화면에 정리되어 있다.
- 수집 진단 하단이 bottom navigation에 가리지 않도록 여백을 조정했다.

## 아직 부족한 부분

### 홈

- 월 지출 한도 값은 아직 사용자가 설정한 값이 아니라 UI 구조 검증용 임시값이다.
- 수입/입금 기능이 없으므로 잔액 기반 예산이 아니라 소비 한도 개념으로 제한한다.
- `빌런의 인사이트`는 현재 AI 분석이 아니라 확인 필요 거래를 보여주는 MVP용 대체 구조다.
- 시안처럼 여러 인사이트 카드가 쌓이는 구조는 아직 없다.
- 가맹점 아이콘은 실제 로고 asset이 아니라 fallback이다.
- 하단 탭은 현재 `홈/내역/설정` 3개이고, 시안의 `분석` 탭은 아직 없다.

### 내역

- 시안의 내역 화면처럼 기간 필터, 카테고리 필터, 검색 아이콘이 아직 없다.
- 일자별 그룹 헤더와 카드형 거래 묶음은 일부 방향만 맞고, 시안 수준의 밀도와 정렬은 더 다듬어야 한다.
- 가맹점 로고/카테고리 chip 표현을 홈과 일관되게 맞춰야 한다.

### 상세

- 상세 화면은 기능 흐름 중심이고, 시안처럼 상단 로고/금액/시간/카테고리 위계가 더 정교하지는 않다.
- 판별 근거는 개발/검증에는 유용하지만 일반 사용자에게는 정보량이 많다.
- 사용자용 설명과 개발자용 reason code를 분리할 필요가 있다.

### 설정

- 권한 안내 문구는 MVP 기준으로 충분하지만, 실제 배포 전에는 Google Play 정책 리스크를 고려해 더 신중한 문구가 필요하다.
- debug seed와 수집 진단은 개발자 기능이므로, 릴리즈 빌드에서는 숨김 또는 별도 진입 방식이 필요하다.

## 제품 범위 판단

현재 MVP의 핵심은 다음 흐름이다.

1. 결제 알림 자동 수집
2. 중복/이체/충전/취소성 이벤트 제외 판별
3. 실제 지출 저장
4. 홈에서 확인

따라서 당장 만들지 않을 영역은 다음과 같다.

- 수입/입금 기반 잔액 관리
- 고도화된 예산 관리
- 고급 AI 소비 인사이트
- MyData 연동
- iOS 자동 수집

다만 홈 UI에서 한도 대비 진행률 영역은 시안 구조상 필요하므로, 기능적으로는 `월 지출 한도` 개념으로 제한하는 것이 안전하다.

## 다음 작업 우선순위

1. 내역 화면 시안 비교: 필터, 검색, 일자 그룹, 거래 카드 밀도를 현재 구현과 비교한다.
2. 내역 화면 1차 재정렬: 홈에서 만든 merchant fallback과 category chip을 내역에도 맞춘다.
3. 상세 화면 사용자/개발자 정보 분리: 일반 사용자에게 보여줄 판별 설명과 reason code를 나눈다.
4. Android 수집 전 체크리스트 갱신: 실제 기기 테스트 전 권한/수신/저장 흐름을 점검 문서로 정리한다.

## 현재 결론

홈은 시안의 핵심 구조에 가까워졌지만, 아직 기능적 의미와 문구를 다듬어야 한다. 내역과 상세는 동작 구조는 있으나 시안 수준의 정렬, 밀도, 사용자 설명은 부족하다. 다음 UI 작업은 홈을 계속 확장하기보다 내역 화면을 시안 기준으로 맞추는 것이 더 효율적이다.
